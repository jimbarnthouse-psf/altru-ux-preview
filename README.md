# Altru suggested user flows

Prepared by **Specbee for Altru**, using Altru's existing website design. These suggested flows are provided solely to explore and discuss potential visitor journeys.

- [Start the annotated client walkthrough](https://jimbarnthouse-psf.github.io/altru-ux-preview/review.html)
- [Explore the separate interactive mockup](https://jimbarnthouse-psf.github.io/altru-ux-preview/)
- [Illustrated UX guide - thirteen pages, PDF](https://jimbarnthouse-psf.github.io/altru-ux-preview/Altru-UX-Approach-Guide.pdf)
- [Executive brief - one page, PDF](https://jimbarnthouse-psf.github.io/altru-ux-preview/Altru-UX-Executive-Brief.pdf)

The review offers seven distinct visitor goals across 47 prepared full-site views. Each example begins on Home and shows the appropriate website navigation: Find a Provider, Services, or Locations. Known-doctor search highlights the office phone directly on the profile. Familiar-clinic search starts in Locations, opens the clinic page, and follows View providers. The service-to-provider journey follows Services → Heart & Vascular Care → read the overview → Find a provider, ending on matching heart-care providers. Clinical topics remain optional through the separate diagnosis/treatment journey. Service journeys introduce the care before showing relevant providers or local capabilities, and use an approximate IP-based location for nearby care. The estimate is labeled and can be changed using a city, ZIP or community. The nearby-provider example demonstrates a correction; local-service comparison uses the estimate directly. The clinic journey includes the location page’s Services and Getting Here links before directions.

Every journey opens paused, including after restart or choosing another path. Optional Play demonstrates the website visitor’s actions, including opening the phone menu; Replay step demonstrates one action and pauses on its destination. Explanations remain visible outside the site viewport. Back, Next and restart let a reviewer inspect the sequence, and Desktop/Phone changes the illustrated device. Each path ends with an explanation and a question for review. These are suggested examples; visitors can also enter the real site directly on a service, provider or location page.

“Understand Altru’s approach” and “Find specialized care farther away” are removed as standalone paths. “Help someone in another community” is covered by explicit starting-location selection in the nearby-provider journey. “Recover from no matches” is an interaction variation rather than a standalone visitor goal; the separate working mockup retains that behavior.

The review uses complete frozen HTML copies of the Altru concept with shared Altru styling and assets, including the header, navigation, page content, footer and background behind overlays. The diagnosis/treatment journey begins with the website’s Services menu, then Heart & Vascular Care, then a clinical topic and its information destination. The parent player demonstrates visitor behavior; child pages contain no application scripts, live forms or embedded maps. Only guided links and the annotated care-type selection advance manually; the guided phone navigation button can open the menu without starting playback. Prepared search examples show their query and suggestion when paused. Phone, clinical-information and Google Maps handoffs are illustrated; the clinical path includes an attributed desktop/phone capture of the existing Altru.org electrophysiology page. No external reference opens automatically in the reviewer’s real browser, and the phone demonstration never places a call. IP-based detection is simulated with anonymous/sample locations; the review makes no IP lookup and requests no device-location permission. The separate interactive mockup and both PDFs retain their existing links and content.

Journeys start paused for everyone. Reduced-motion preference removes spatial animation. Reading holds and click feedback remain available. Switching journeys, steps or devices cancels the prior animation. Playback pauses when the document is hidden. Prepared inputs stay inert even while the player illustrates typing; use the separate mockup for free exploration.

The incoming region remains anonymous. Added provider identities, care offerings, relationships and distances are illustrative. Provider practice relationships do not establish local procedure capability. There is no live availability or appointment routing; scheduling remains in MyChart. Production TruSearch configuration and clinical content relationships require Altru's validation.

GitHub Pages publishes the review, its prepared screens and shared assets, the independent original mockup, and the two PDFs from the main branch root.
