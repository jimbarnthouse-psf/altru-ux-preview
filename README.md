# Altru suggested user flows

Prepared by **Specbee for Altru**, using Altru's existing website design. These suggested flows are provided solely to explore and discuss potential visitor journeys.

- [Start the annotated client walkthrough](https://jimbarnthouse-psf.github.io/altru-ux-preview/review.html)
- [Explore the separate interactive mockup](https://jimbarnthouse-psf.github.io/altru-ux-preview/)
- [Illustrated UX guide - fifteen pages, PDF](https://jimbarnthouse-psf.github.io/altru-ux-preview/Altru-UX-Approach-Guide.pdf)
- [Executive brief - one page, PDF](https://jimbarnthouse-psf.github.io/altru-ux-preview/Altru-UX-Executive-Brief.pdf)

The review offers seven distinct visitor goals across 44 prepared full-site views. Each example begins on Home and shows the appropriate website navigation: Find a Provider, Services, or Locations. Known-doctor search highlights the office phone directly on the profile. Familiar-clinic search starts in Locations, opens the clinic page, and follows View providers. The service-to-provider journey follows Services → Heart & Vascular Care → read the overview → Find a provider, ending on matching heart-care providers. Clinical topics remain optional through the separate diagnosis/treatment journey. Service journeys introduce the care before showing relevant providers or local capabilities, and use an approximate IP-based location for nearby care. The estimate is labeled and can be changed using a city, ZIP or community. The nearby-provider example demonstrates a correction; the nearby-offerings journey uses the estimate directly to show what care each location offers. Visitors browse all care types, may open a local offering for details, and finish without provider selection. The clinic journey includes the location page’s Services and Getting Here links before directions.

Every journey opens paused, including after restart or choosing another path. Optional Play demonstrates the website visitor’s actions, including opening the phone menu; Replay step demonstrates one action and pauses on its destination. Explanations remain visible outside the site viewport. Back, Next and restart let a reviewer inspect the sequence, and Desktop/Phone changes the illustrated device. Each path ends with an explanation and a question for review. These are suggested examples; visitors can also enter the real site directly on a service, provider or location page.

“Understand Altru’s approach” and “Find specialized care farther away” are removed as standalone paths. “Help someone in another community” is covered by explicit starting-location selection in the nearby-provider journey. “Recover from no matches” is an interaction variation rather than a standalone visitor goal; the separate working mockup retains that behavior.

The review uses complete frozen HTML copies of the Altru concept with shared Altru styling and assets, including the header, navigation, page content, footer and background behind overlays. The diagnosis/treatment journey begins with the website’s Services menu, then Heart & Vascular Care, then a clinical topic and its information destination. The parent player demonstrates visitor behavior; child pages contain no application scripts, live forms or embedded maps. Only highlighted website actions and guidance links advance manually; the guided phone navigation button can open the menu without starting playback. Prepared search examples show their query and suggestion when paused. Phone, clinical-information and Google Maps handoffs are illustrated; the clinical path includes an attributed desktop/phone capture of the existing Altru.org electrophysiology page. No external reference opens automatically in the reviewer’s real browser, and the phone demonstration never places a call. IP-based detection is simulated with anonymous/sample locations; the review makes no IP lookup and requests no device-location permission. The separate interactive mockup, illustrated guide and executive brief now follow these same approved goals while keeping their established shareable links.

Journeys start paused for everyone. Reduced-motion preference removes spatial animation. Reading holds and click feedback remain available. Switching journeys, steps or devices cancels the prior animation. Playback pauses when the document is hidden. Prepared inputs stay inert even while the player illustrates typing; use the separate mockup for free exploration.

The incoming region remains anonymous. Added provider identities, care offerings, relationships and distances are illustrative. Provider practice relationships do not establish local procedure capability. There is no live availability or appointment routing; scheduling remains in MyChart. Production TruSearch configuration and clinical content relationships require Altru's validation.

GitHub Pages publishes the review, its prepared screens and shared assets, the independent interactive mockup, both PDFs and a downloadable review ZIP from the main branch root.

## Downloaded package

[Download the complete review package](https://jimbarnthouse-psf.github.io/altru-ux-preview/Altru-UX-Review-Package.zip). It contains the public review, all 44 prepared screens and shared assets, the self-contained `index.html` mockup, both PDFs and this README. It excludes internal notes, source-call material and development records.

Use the hosted review for the simplest experience. For local review, serve the extracted folder using a local HTTP server (for example, `python3 -m http.server 8080`) and open `http://localhost:8080/review.html`. The prepared iframe review requires HTTP. Double-clicking `index.html` opens the self-contained free-exploration mockup; clinical links, Google Maps and hosted review/download links require internet access. Its phone links are normal contact links; only the guided review simulates the call handoff.

The interactive mockup starts with a labeled, simulated approximate location. Explicit changes persist for the visit and override the estimate. It performs no IP lookup or device-location request. The known-doctor example features the verified office phone above care locations; other facility contacts are labeled separately.
