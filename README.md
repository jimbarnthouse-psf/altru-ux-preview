# Altru suggested user flows

Prepared by **Specbee for Altru**, using Altru's existing website design. These suggested flows are provided solely to explore and discuss potential visitor journeys.

- [Start the annotated client walkthrough](https://jimbarnthouse-psf.github.io/altru-ux-preview/review.html)
- [Explore the original clickable mockup](https://jimbarnthouse-psf.github.io/altru-ux-preview/)
- [Illustrated UX guide - thirteen pages, PDF](https://jimbarnthouse-psf.github.io/altru-ux-preview/Altru-UX-Approach-Guide.pdf)
- [Executive brief - one page, PDF](https://jimbarnthouse-psf.github.io/altru-ux-preview/Altru-UX-Executive-Brief.pdf)

The review starts with instructions and a card describing each visitor's goal. Eleven paths and 47 annotated steps cover service learning, diagnosis/treatment information, Altru's care approach, known providers, familiar-clinic provider searches, nearby care, local offerings, care farther away, clinic/hospital details, caregiver context and no-match recovery. Use the outlined controls in the working mockup, or Next to preview a prepared example state. Back, restart, restore and a path chooser remain available. On a phone, notes can collapse for more room. Each path ends with an explanation and a question for review.

The original mockup remains at its existing address. Its unified search accepts a provider name, specialty or clinic, with an optional city/ZIP. Service pages offer useful content before provider and place discovery. Clinical learning links open existing Altru.org pages in new tabs. Local Heart & Vascular offerings connect to their relevant sample teams; other service pages show provider practice relationships rather than asserting local treatment capability. Verified addresses can open Google Maps directions.

The incoming region remains anonymous. Added provider identities, care offerings, relationships and distances are illustrative. There is no live availability or appointment routing; scheduling remains in MyChart. Production TruSearch configuration and clinical content relationships require Altru's validation.

GitHub Pages publishes the original mockup, annotated review assets and the two PDFs from the main branch root. The client review needs HTTP/HTTPS so its same-origin working mockup can communicate with the annotation layer. Maps and external information need internet access.
